## 1. האופטימיזציה המרכזית — precache של 50MB ירד ל-7.8MB

### הבעיה

ה-service worker עשה precache ל-**50.9MB** (178 קבצים) בכל התקנה ובכל עדכון
של האפליקציה. כלומר: כל מתפלל שהתקין את ה-PWA, וכל מכשיר שקיבל עדכון גרסה,
הוריד כ-50MB **לפני** שהאפליקציה הפכה לשמישה.

זה קרה למרות שכל התוכן הכבד — חמשת חומשי התורה, הסידורים והפרשנים מספריא —
כבר נטען עצלנית דרך `import()` דינמי. כלומר ה-precache הוריד מראש תוכן
שהמשתמש ברוב המקרים לעולם לא פותח.

הסיבה: `globIgnores` כלל רק `**/assets/data-*.js` (חמשת החומשים), אבל לא את
הסידורים (`siddur_*.js`, כ-11MB) ולא את הפרשנים (`*_on_*.js`, כ-32MB).

### התיקון

ב-`vite.config.ts` הורחב `globIgnores` כך שה-precache מכיל **רק את מעטפת
האפליקציה**:

```js
globIgnores: [
  '**/assets/data-*.js',    // חומשים: בראשית .. דברים
  '**/assets/siddur_*.js',  // נוסחי הסידור
  '**/assets/*_on_*.js',    // פרשני ספריא
],
```

### התוצאה — נמדד בפועל

| | לפני | אחרי | שיפור |
|---|---|---|---|
| נפח precache | 50.9 MB | **7.8 MB** | **−84%** |
| מספר רשומות | 178 | 112 | −37% |

אומת ישירות מול `dist/sw.js` שנוצר: 112 רשומות, **0** קבצי תוכן כבד.

## 2. באג: כלל ה-runtime caching מעולם לא עבד

### הבעיה

הכלל היחיד ב-`runtimeCaching` היה:

```js
urlPattern: /\.json$/
```

אבל בבנייה לפרודקשן Vite הופך את קובצי ה-JSON ל-chunks של **`.js`** עם hash
בשם. כלומר הביטוי הזה **לא התאים לאף קובץ אי פעם** בפרודקשן. הקוד היה מת.

זו לא הייתה בעיה בולטת קודם רק מפני שה-precache (הבעיה מסעיף 1) כיסה על זה
בכך שהוריד הכל מראש. ברגע שמוציאים את התוכן מה-precache — הכלל הזה הופך
לקריטי.

### התיקון

```js
urlPattern: /\/assets\/(data-|siddur_|[^/]*_on_)[^/]*\.js$/,
handler: 'CacheFirst',
```

`CacheFirst` בטוח כאן מפני שיש hash של תוכן בשם הקובץ — בנייה חדשה היא כתובת
חדשה, ולכן אי אפשר להיתקע על גרסה ישנה.

### המשמעות למשתמש

התנהגות הקריאה לא נפגעה — היא רק נדחתה לרגע הנכון:

- **לפני:** 50MB בהתקנה, גם למי שרק בודק זמני תפילות.
- **אחרי:** התקנה מהירה. ספר או סידור יורד פעם אחת, כשפותחים אותו בפועל,
  ומאותו רגע זמין גם אופליין.

**נבדק בפועל:** נטען `/siddur` בבילד פרודקשן — הסידור מוצג במלואו עם ניקוד
וטעמים.

`@typescript-eslint/no-require-imports`:

```diff
+ import tailwindcssAnimate from "tailwindcss-animate";
- plugins: [require("tailwindcss-animate")],
+ plugins: [tailwindcssAnimate],
```

בנוסף נוקו 5 הנחיות `eslint-disable` מיותרות (`eslint --fix`).

**תוצאה:** מ-1 שגיאה + 52 אזהרות → **0 שגיאות** + 47 אזהרות.
האזהרות שנותרו הן ברובן `react-hooks/exhaustive-deps` — הן דורשות שיפוט לגבי
כוונת הקוד, ולכן לא נגעתי בהן. שינוי אוטומטי של תלויות hook הוא דרך מוכרת
להכניס באגים.
