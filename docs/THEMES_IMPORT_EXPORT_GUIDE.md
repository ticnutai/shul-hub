# מדריך מלא: ייבוא וייצוא ערכות נושא ללוח הטלוויזיה (Android TV)

**למי המסמך:** למי שרוצה להביא ערכות נושא (צבעים) וגרדיאנטים ללוח בית הכנסת:
מנהל שמעביר עיצוב בין בתי כנסת, מעצב שעובד בפיגמה, ומפתח שרוצה לייצר קבצים
מתוכנה אחרת או לממש את אותו פורמט אצלו.

**מצב נכון ל-24/09/2026.** כל מה שכתוב כאן נבדק מול הקוד. הדוגמאות וההודעות
הועתקו מהרצה אמיתית של קוד הייבוא, לא נכתבו מהזיכרון.

> **בקצרה:** מערכת ייבוא/ייצוא ללוח **כבר קיימת ועובדת**: ניהול ← טלוויזיה ←
> לשונית **כלים**. הפורמט נקרא `design-tokens`, והוא מתאר ערכה ב-10 **תפקידים**
> (רקע, טקסט, הדגשה...) ולא בשמות משתנים. ערכה שמיובאת ונשמרת מגיעה לקופסה
> בתוך שניות, **בלי להתקין APK מחדש**.

## 1. מה קיים ומה לא

באפליקציה יש **שלוש** מערכות ערכות נושא נפרדות. רק אחת מהן יודעת לייבא ולייצא לקובץ.

| מערכת | איפה | כמה מובנות | ערכות אישיות | ייבוא/ייצוא לקובץ | פיגמה |
|---|---|---|---|---|---|
| **לוח הטלוויזיה** | ניהול ← טלוויזיה | 7 | עד 24 | ✅ קובץ או הדבקה | ✅ תוסף + קובץ JSON |
| **גרדיאנטים של הלוח** | אותו מקום | 8 | עד 40 | ✅ באותו קובץ | ❌ |
| **האתר** (צבעי הממשק) | הגדרות | 16 | כן, בחשבון המשתמש | ❌ | ❌ |
| **הסידור** | סידור ← 🎨 | כמה מובנות | כן, עם פרסום לציבור | ❌ | ❌ |

שבע הערכות המובנות של הלוח: לילה כחול (ברירת המחדל), זהב מלכותי, ירוק שבת,
מודרני, אבן ירושלים, שבת קודש ודפוס.

**Skill:** מותקן כרגע רק skill אחד, להרצת מיגרציות. אין skill ייעודי לערכות נושא.
מה שהכי קרוב לזה הוא **הערכה להטמעה** `docs/design-tokens-kit/`: קובץ TypeScript
עצמאי שמממש את כל הפורמט, ומיועד להעתקה לפרויקט אחר (סעיף 9).

## 2. איך ערכה מגיעה למסך הטלוויזיה

זו הנקודה החשובה ביותר ל-Android TV: **ערכת נושא היא נתונים, לא קוד.** היא נשמרת
בהגדרות הלוח במסד הנתונים, והקופסה מושכת אותה. לכן אין צורך לבנות APK, להתקין
מחדש או לגעת בשלט.

```
 ┌──────────────────────── דפדפן המנהל ─────────────────────────┐
 │                                                               │
 │  קובץ .json ──┐                                               │
 │  הדבקה ───────┼──►  ייבוא  ──►  טיוטה  ──►  תצוגה מקדימה חיה  │
 │  פיגמה ───────┘                   │                           │
 │                                   │  "שמור ושדר"              │
 └───────────────────────────────────┼───────────────────────────┘
                                     ▼
                ┌──────────── Supabase ────────────┐
                │  טבלת tv_config  (שורה לכל קהילה)  │
                │    theme:        "c_k3j9x2ab"      │ ◄── איזו ערכה פעילה
                │    customThemes: [ ...עד 24 ]      │ ◄── הערכות שיובאו/נוצרו
                │    gradients:    [ ...עד 40 ]      │
                └───────────────┬──────────────────┘
                                │  Realtime: "tv_config השתנתה"
                                ▼
                ┌──────── קופסת Android TV ─────────┐
                │  useDeviceLink  ← מושך מחדש         │
                │  normalizeTvConfig  ← מאמת שוב      │
                │  useOfflineSnapshot ← שומר עותק     │
                │  ↓                                  │
                │  משתני CSS על הלוח  →  המסך מתעדכן   │
                └─────────────────────────────────────┘
```

שלושה דברים שכדאי לדעת:

- **שום דבר לא מגיע למסך עד "שמור ושדר".** ייבוא נכנס לטיוטה בלבד, ואפשר לראות,
  לתקן או לבטל בלי שאף מתפלל ראה.
- **הקופסה מאמתת את ההגדרות פעם נוספת** (`normalizeTvConfig`) לפני שהיא מציגה אותן.
  אפילו שורה ששונתה ידנית במסד הנתונים לא יכולה להכניס ערך מסוכן למסך.
- **בלי אינטרנט הלוח ממשיך עם העותק האחרון** (`useOfflineSnapshot`), כולל הערכה.

## 3. האנטומיה של ערכת נושא: 10 תפקידים

ערכה בלוח היא **עשרה צבעים**. כל צבע אחר על המסך נגזר מהם (גוונים רכים יותר
מחושבים ב-`color-mix`). לכן מספיק לשנות צבע אחד כדי שכל הלוח יתעדכן לפיו.

בקובץ הצבעים לא מופיעים בשמות המשתנים של הלוח (`--tv-accent`) אלא ב**תפקידים**,
כלומר במה שהצבע *עושה*. ככה קובץ שנוצר בתוכנה אחרת עדיין מובן כאן.

| # | תפקיד בקובץ | משתנה בלוח | שם בממשק | איפה רואים אותו | דוגמה (לילה כחול) |
|---|---|---|---|---|---|
| 1 | `background` | `--tv-bg-a` | רקע ראשי | כל הרקע | `#0b1628` |
| 2 | `backgroundGlowTop` | `--tv-bg-b` | הילה עליונה | זוהר רך בראש המסך | `#1b3054` |
| 3 | `backgroundGlowBottom` | `--tv-bg-c` | הילה תחתונה | זוהר רך בתחתית | `#16304f` |
| 4 | `surface` | `--tv-panel` | רקע כרטיסים | רקע הלוחות והכרטיסים | `rgba(255, 255, 255, 0.045)` |
| 5 | `text` | `--tv-text` | טקסט | טקסט רגיל | `#f4f7fb` |
| 6 | `textMuted` | `--tv-text-dim` | טקסט משני | תאריכים, הערות, תוויות | `#9fb2cc` |
| 7 | `accent` | `--tv-accent` | צבע מודגש | כותרות, שעות, מסגרות זהב | `#f0c35c` |
| 8 | `accentAlt` | `--tv-accent-2` | צבע משני | הדגשה שנייה, צלליות זהב | `#b99236` |
| 9 | `onAccent` | `--tv-on-accent` | טקסט על צבע מודגש | טקסט בתוך תגית זהב | `#0b1628` |
| 10 | `highlight` | `--tv-pinned` | מודעה נעוצה | מודעה נעוצה, התראות | `#ef8f4c` |

### זוגות שחייבים ניגודיות

אלה הזוגות שנקראים ממרחק, באולם מואר. כשבונים ערכה, זה הדבר הראשון לבדוק:

| טקסט | על רקע | למה זה קריטי |
|---|---|---|
| `text` | `background` / `surface` | רוב הטקסט על המסך |
| `accent` | `background` / `surface` | השעות, מה שמחפשים מהדלת |
| `onAccent` | `accent` | טקסט בתוך תגית. זו הטעות הנפוצה ביותר |
| `textMuted` | `surface` | "משני" לא אומר "בלתי קריא" |

**ערכה כהה או בהירה (`mode`):** ברירת המחדל כהה, ויש לזה סיבה. מסך OLED שמציג
מסך בהיר וקבוע במשך שבועות **נצרב**. ערכות בהירות מתאימות למסכי LCD ולשבת.

## 4. מדריך למנהל: ייצוא וייבוא מהממשק

### איפה

```
  ניהול ──► טלוויזיה ──► ┌──────┬───────┬───────┬──────┐
                         │ עיצוב │ פריסה │ תוכן  │ כלים │ ◄── כאן
                         └──────┴───────┴───────┴──────┘
                                                   │
                         ┌─────────────────────────┴───────────────┐
                         │  ▸ ייבוא וייצוא                          │
                         │  ▸ ייבוא מפיגמה                          │
                         └─────────────────────────────────────────┘
```

### ייצוא (גיבוי, או העברה לבית כנסת אחר)

```
┌─ ייבוא וייצוא ────────────────────────────────────────────────┐
│ ייצוא — לגיבוי או להעברה לבית כנסת אחר                         │
│                                                                │
│  [ הכל ]  [ ערכות נושא ]  [ גרדיאנטים ]   ← בוחרים מה לייצא     │
│  [ 📋 העתקה ללוח ]                         ← או העתקה כטקסט     │
│                                                                │
│ ייבוא                                                          │
│  [ 📁 בחירת קובץ ]                                              │
│  ┌──────────────────────────────────────────┐                  │
│  │ …או להדביק כאן את תוכן הקובץ              │  [ ייבוא ]       │
│  └──────────────────────────────────────────┘                  │
└────────────────────────────────────────────────────────────────┘
```

- **מה מיוצא:** רק ערכות וגרדיאנטים **שיצרתם או ייבאתם**. ערכות מובנות לא מיוצאות,
  כי הן קיימות בכל מערכת ממילא. אם אין עדיין כאלה, תופיע ההודעה
  "אין עדיין ערכות נושא או גרדיאנטים משלכם לייצוא".
- **שם הקובץ:** `לוח-ערכות-נושא-2026-09-24.json` (או `לוח-גרדיאנטים-…`, `לוח-עיצוב-…`).
- **שום דבר לא עולה לשרת.** הקובץ נוצר בדפדפן ויורד אליכם.

### ייבוא

1. **בחירת קובץ**, או הדבקת התוכן בתיבה ולחיצה על **ייבוא**.
2. מופיעה הודעה עם מה שנכנס, למשל:
   `יובאו 3 ערכות נושא ו-2 גרדיאנטים · 2 פריטים לא תקינים דולגו. לחצו "שמור ושדר" כדי להחיל.`
3. הערכות מופיעות ברשימת הערכות בלשונית **עיצוב**, **כטיוטה**.
4. בוחרים ערכה, בודקים בתצוגה המקדימה (או ב**חלון חי** על מסך שני).
5. **שמור ושדר**, והמסך בבית הכנסת מתעדכן תוך שניות.

**הייבוא מוסיף ולעולם לא מוחק.** אם שם כבר תפוס, מתווסף מספר:

```
  לפני הייבוא:       ייבוא של "חגים":      ייבוא נוסף של אותו קובץ:
  ┌──────────┐       ┌──────────┐         ┌──────────┐
  │ חגים     │  ──►  │ חגים     │   ──►   │ חגים     │
  └──────────┘       │ חגים (2) │         │ חגים (2) │
                     └──────────┘         │ חגים (3) │
                                          └──────────┘
```

(נבדק: ייבוא אותו קובץ פעמיים נתן `["חגים", "חגים (2)"]`.)

## 5. פורמט הקובץ, שדה אחר שדה

זה ייצוא **אמיתי** של הערכה "לילה כחול", כפי שהקוד מייצר אותו:

```json
{
  "format": "design-tokens",
  "version": 1,
  "app": "shul-hub-tv",
  "exportedAt": "2026-09-24T12:00:00.000Z",
  "themes": [
    {
      "name": "לילה כחול",
      "description": "כחול עמוק וזהב — ברירת המחדל",
      "mode": "dark",
      "roles": {
        "background": "#0b1628",
        "backgroundGlowTop": "#1b3054",
        "backgroundGlowBottom": "#16304f",
        "surface": "rgba(255, 255, 255, 0.045)",
        "text": "#f4f7fb",
        "textMuted": "#9fb2cc",
        "accent": "#f0c35c",
        "accentAlt": "#b99236",
        "onAccent": "#0b1628",
        "highlight": "#ef8f4c"
      }
    }
  ],
  "gradients": [
    { "name": "ערב", "value": "linear-gradient(160deg, #0b1628, #1b3054)" }
  ]
}
```

| שדה | חובה? | מה מותר | הערות |
|---|---|---|---|
| `format` | **כן** | בדיוק `"design-tokens"` | מה שמבדיל קובץ עיצוב מכל JSON אחר |
| `version` | רצוי | מספר שלם, כרגע `1` | גרסה גבוהה מ-1 **נדחית**, המערכת לא מנחשת |
| `app` | לא | כל מחרוזת | למידע בלבד. אסור לקוד להתנהג אחרת לפיו |
| `exportedAt` | לא | תאריך ISO | למידע בלבד |
| `themes` | לא | מערך | קובץ עם גרדיאנטים בלבד הוא קובץ תקין |
| `themes[].name` | **כן** | עד 40 תווים | שם ארוך נחתך. שם תפוס מקבל "(2)" |
| `themes[].description` | לא | עד 80 תווים | |
| `themes[].mode` | רצוי | `"light"` / `"dark"` | בלי השדה הערכה נחשבת כהה |
| `themes[].roles` | **כן** | מפה של תפקיד ← צבע | **תפקיד חסר מותר** (ראה למטה) |
| `gradients[].name` | **כן** | עד 40 תווים | |
| `gradients[].value` | **כן** | CSS gradient | ראה סעיף 7 |

**אין מזהים (`id`) בקובץ, ובכוונה.** המזהים נוצרים מחדש בכל ייבוא, ולכן ייבוא
לעולם לא דורס ערכה קיימת.

### תפקיד חסר: הערכה משלימה את עצמה

קובץ מתוכנה עם פלטה קטנה יותר עדיין מייבא ערכה שלמה. כל תפקיד שחסר נלקח מערכת
ברירת המחדל (לילה כחול). זו התוצאה האמיתית של ייבוא ערכה עם 3 תפקידים בלבד:

```
  בקובץ (3 תפקידים):              בלוח אחרי הייבוא (10 משתנים):
  ─────────────────               ─────────────────────────────────
  background  #101828   ────────► --tv-bg-a       #101828   ◄ מהקובץ
                                  --tv-bg-b       #1b3054     ברירת מחדל
```

## 7. אימות ואבטחה: מה נדחה ולמה

קובץ מגיע ממישהו אחר, והערכים שלו נכנסים בסוף ל-`style` על מסך שאף אחד לא
משגיח עליו. לכן כל ערך עובר בדיקה, ו**אותה פונקציית בדיקה** משמשת גם שמירה רגילה
וגם ייבוא. אילו היו שתי דרכים להכניס נתונים, אחת מהן הייתה פחות בטוחה.

### צבע: רק הצורות האלה

```
  #rgb   #rrggbb   #rrggbbaa   rgb(…)   rgba(…)   hsl(…)   hsla(…)
```

לא עוברים: שמות צבעים (`red`, `gold`), `oklch()`, `color-mix()`, `var(--x)`, `transparent`.

> ערכה שאחד מעשרת הצבעים שלה לא עבר **נדחית כולה** ונספרת כ"דולגה". המערכת לא
> מציגה ערכה חלקית. לכן בקבצים משתמשים ב-hex.

### גרדיאנט: רק פונקציות גרדיאנט, רק תווים בטוחים

```
  ✅ linear-gradient(160deg, #0b1628, #1b3054)
  ✅ radial-gradient(circle at 50% 0%, #f0c35c, #0b1628 70%)
  ✅ conic-gradient(…)     ✅ repeating-linear-gradient(…)

  ❌ url(…)            בקשת רשת שחושפת מי צופה במסך
  ❌ var(…)            שאיבת ערכים ממשתנים אחרים
  ❌ ;  {  }  \  < >   יציאה מההצהרה והזרקת כללי CSS
  ❌ image-set, attr(, expression, @import
  ❌ יותר מ-600 תווים  ניפוח של מסד הנתונים
  ❌ כל מה שהדפדפן עצמו לא מכיר כ-background-image
```

### נבדק על הקוד הזה

ייבוא של קובץ עם ערכה תקינה, ערכה עם `url(https://evil.example/x.png)`, גרדיאנט
תקין וגרדיאנט עם `; background:url(x)`:

```
  themes:    ["חגים"]
  gradients: ["ערב = linear-gradient(160deg, #0b1628, #1b3054)"]
  skipped:   2      ← שני הפריטים העוינים נדחו ונספרו
```

### א. התוסף "שלח ללוח" (הכי מהיר)

התקנה חד-פעמית: Figma Desktop ← Plugins ← Development ← **Import plugin from
manifest…** ← `figma-plugin/manifest.json`. אחר כך: Plugins ← Development ←
**שלח ללוח - קרובים**. בפעם הראשונה מדביקים את כתובת האתר (`https://shul-hub.lovable.app`).

למה תוסף ולא חיבור ישיר: ה-REST API של משתני פיגמה זמין רק בתוכנית Enterprise.
תוסף רץ בתוך פיגמה, ושם המשתנים זמינים בכל תוכנית.

הפרטיות: הצבעים נוסעים ב**חלק שאחרי `#`** בכתובת (`#figma=...`). דפדפנים לא שולחים
את החלק הזה לשום שרת. אין טוקן, אין העלאה ואין צד שלישי באמצע.

### ב. קובץ JSON מפיגמה

לשונית **כלים** ← **ייבוא מפיגמה** ← גוררים קובץ. ארבע הצורות שנתמכות:

**1. גוף ה-REST API** (`variables/local`): צבעים כ-`{r,g,b,a}` בטווח 0..1
```json
{ "meta": { "variables": { "VariableID:1:2": {
    "name": "brand/primary", "resolvedType": "COLOR",
    "valuesByMode": { "1:0": { "r": 0.94, "g": 0.76, "b": 0.36, "a": 1 } } } } } }
```

**2. תקן W3C (Design Tokens):** קבוצות מקוננות עם `$value`
```json
{ "color": { "bg": { "$type": "color", "$value": "#0b1628" },
             "brand": { "primary": { "$type": "color", "$value": "#f0c35c" } } } }
```

**3. Tokens Studio (הישן):** אותו דבר עם `value` / `type` בלי `$`
```json
{ "global": { "background": { "value": "#0b1628", "type": "color" } } }
```

**4. מפה פשוטה** של שם ← צבע
```json
{ "background": "#0b1628", "text": "#f4f7fb", "accent": "#f0c35c" }
```

מה שאינו צבע (ריווחים, רדיוסים, טיפוגרפיה) מתעלמים ממנו. נקראים עד 200 צבעים.
למשתנה עם כמה מצבים (Light/Dark) נלקח **המצב הראשון** בלבד, שהוא ברירת המחדל של הקובץ.
כדי לייבא את מצב Dark, מייצאים אותו כקובץ נפרד או משנים את הסדר בפיגמה.

### ג. דרך Claude (MCP)

המחבר הרשמי של פיגמה מחובר לחשבון Claude. מעתיקים קישור לפריים (קליק ימני ←
**Copy link to selection**) ומבקשים בצ'אט: "קח את המסך הזה ובנה ממנו ערכת נושא
ללוח". הפרטים ב-[`DESIGN_MCP.md`](DESIGN_MCP.md).

**מתי זה לא יעזור:** אם העיצוב הוא **תמונה** (JPG, צילום של לוח מודפס), אין

### איך המערכת מנחשת איזה צבע הוא איזה תפקיד

לפי **שם** המשתנה. הכללים נבדקים לפי הסדר: הראשון שמתאים זוכה, וצבע אחד לא יכול

## 9. למפתחים: לייצר קובץ מתוכנה אחרת

### הכלל: תפקידים, לא משתנים

כל תוכנה מחזיקה **טבלה אחת** שמתרגמת בין המשתנים שלה לתפקידים. זה הדבר היחיד
ששתי התוכנות צריכות להסכים עליו.

```
   התוכנה שלך                    הקובץ                       הלוח
  ───────────────             ──────────────             ───────────────
  --my-bg        ─┐                                 ┌─►  --tv-bg-a
  --my-card      ─┼─► VAR_BY_ROLE ─► roles{} ─► VAR_BY_ROLE ─┼─►  --tv-panel
  --my-brand     ─┘      (שלך)                    (של הלוח) └─►  --tv-accent
```

### ייצוא מתוכנה אחרת: שלד מינימלי (TypeScript)

```ts
const ROLES = [
  "background", "backgroundGlowTop", "backgroundGlowBottom", "surface",
  "text", "textMuted", "accent", "accentAlt", "onAccent", "highlight",
] as const;

// המשתנים שלכם, לפי תפקיד. תפקיד שאין לכם - השמיטו.
const VAR_BY_ROLE: Partial<Record<(typeof ROLES)[number], string>> = {
  background: "--my-bg",
  surface: "--my-card",
  text: "--my-text",
  accent: "--my-brand",
};

export function exportForBoard(themes: { name: string; light: boolean; vars: Record<string, string> }[]) {
  return {
    format: "design-tokens",
    version: 1,
    app: "my-app",
    exportedAt: new Date().toISOString(),
    themes: themes.map((t) => ({
      name: t.name.slice(0, 40),
      mode: t.light ? "light" : "dark",
      roles: Object.fromEntries(
        ROLES.filter((r) => VAR_BY_ROLE[r]).map((r) => [r, t.vars[VAR_BY_ROLE[r]!]]),
      ),
    })),
    gradients: [],
  };
}

// הורדה כקובץ, בלי שרת:
function download(data: unknown, name = "themes.json") {
  const url = URL.createObjectURL(new Blob([JSON.stringify(data, null, 2)], { type: "application/json" }));
  Object.assign(document.createElement("a"), { href: url, download: name }).click();
  URL.revokeObjectURL(url);
}
```

### לממש ייבוא *וגם* ייצוא בפרויקט אחר

אין צורך לכתוב מאפס. [`design-tokens-kit/design-tokens.ts`](design-tokens-kit/design-tokens.ts)
הוא מימוש מלא, בלי תלויות, שמיועד להעתקה. בראש הקובץ מתאימים שני דברים בלבד:
`VAR_BY_ROLE` ו-`DEFAULT_VARS`. ההוראות ב-[`design-tokens-kit/README.md`](design-tokens-kit/README.md).
המפרט הפורמלי המלא ב-[`DESIGN_TOKENS_SPEC.md`](DESIGN_TOKENS_SPEC.md).

### חמישה כללים שאסור לשבור

1. **תפקידים, לא שמות משתנים.** `--my-brand` חסר משמעות בתוכנה אחרת, ו-`accent` מובן בכל מקום.
2. **מזהים נוצרים בייבוא.** אף פעם לא לוקחים `id` מהקובץ.
3. **אותה פונקציית אימות** לשמירה ולייבוא.
4. **הייבוא מוסיף ולא מוחק.** שם תפוס מקבל מספר.
5. **גרסה עתידית נדחית במפורש.** לא מנחשים.

### להרחיב את הפורמט בלי לשבור אותו

- **תפקיד חדש:** מותר בגרסה 1. תוכנה שלא מכירה אותו פשוט לא ממפה אותו.
- **גופנים, רדיוסים, צללים:** כמפתחות אחים ל-`roles` (למשל `"typography": {...}`),
  לא בתוכו. תוכנה ישנה תתעלם.
- **שינוי משמעות של תפקיד קיים:** רק זה מחייב `version: 2`.

## 10. מה עובר בקובץ ומה לא

הלוח מורכב מכמה שכבות עיצוב נפרדות. הקובץ נושא **רק צבעים וגרדיאנטים**.

```
  ┌─────────────────────────────────────────────────┐
  │  פריסה          (לוח מלא / מצגת / עמודות)         │  ✗ לא בקובץ
  ├─────────────────────────────────────────────────┤
  │  סגנון (skin)   16 סגנונות: עמודי שיש, פרוכת…     │  ✗ לא בקובץ
  │  מסגרות ופינות  מעוגל / קטום / מגורע…            │  ✗ לא בקובץ
  ├─────────────────────────────────────────────────┤
  │  גופנים         קלאסי / מודרני / רך               │  ✗ לא בקובץ
  ├─────────────────────────────────────────────────┤
  │  ערכת נושא      10 צבעים                          │  ✅ בקובץ
  │  גרדיאנטים      ספרייה של רקעים                   │  ✅ בקובץ
  ├─────────────────────────────────────────────────┤
  │  עריכות על הלוח (צבע של רכיב מסוים)               │  ✗ לא בקובץ
  └─────────────────────────────────────────────────┘
```

זה מכוון. הסגנון קובע **חומרים וצורות** והערכה קובעת **צבעים**, וכל ערכה מתלבשת
על כל סגנון. לכן ערכה שמיובאת מתוכנה אחרת עובדת גם עם "היכל עמודים" וגם עם "נקי".
הפירוט על הסגנונות ב-[`TV_SKINS_GUIDE.md`](TV_SKINS_GUIDE.md).

**גרדיאנט בשימוש לא תלוי בספרייה.** כלל שמשתמש בגרדיאנט שומר את **הערך עצמו**,
לא הפניה. לכן מחיקת גרדיאנט מהספרייה לא משנה אף מסך שכבר משתמש בו.

## 12. הודעות שגיאה: מה הן אומרות ומה עושים

ההודעות האלה הועתקו מהרצה של הקוד:

| ההודעה | הסיבה | מה עושים |
|---|---|---|
| הקובץ אינו בפורמט הנכון (JSON לא תקין) | הקובץ לא JSON: פסיק מיותר, מרכאות "חכמות" מוורד | לבדוק ב-jsonlint.com. לא להעתיק דרך וורד |
| זה לא קובץ עיצוב: חסר שדה format עם הערך design-tokens | JSON אחר, למשל ייצוא מפיגמה ישירות | לקובץ פיגמה יש מקום אחר: **ייבוא מפיגמה**, לא "ייבוא וייצוא" |
| הקובץ נוצר בגרסה חדשה יותר של הפורמט. עדכנו את המערכת ונסו שוב | `version` גדול מ-1 | לעדכן את המערכת, או לבקש מהשולח לייצא בגרסה 1 |
| לא נמצאו ערכות נושא או גרדיאנטים תקינים בקובץ | הכל נדחה באימות | לבדוק צבעים לא נתמכים (`red`, `oklch`) או גרדיאנט עם `url(` |
| יובאו … · N פריטים לא תקינים דולגו | חלק מהפריטים נדחו | לבדוק את הפריטים שחסרים. בדרך כלל צבע בפורמט לא נתמך |
| לא נמצאו צבעים בקובץ. בפיגמה יש לייצא את המשתנים (Variables) כ-JSON | (בייבוא מפיגמה) אין משתני צבע בקובץ | לייצא Variables, או להשתמש בתוסף שקורא גם Paint Styles |
| אין עדיין ערכות נושא או גרדיאנטים משלכם לייצוא | (בייצוא) אין ערכות אישיות | ערכות מובנות לא מיוצאות. צריך לשמור קודם ערכה משלכם |

## 13. הפער: ערכות האתר והסידור

ל**אתר** (צבעי הממשק) ול**סידור** יש ערכות נושא משלהן, כולל שמירת ערכות אישיות
ופרסום לציבור דרך הטבלה `app_themes`. **אין להן ייבוא/ייצוא לקובץ**, והן לא
מדברות עם ערכות הלוח.

אם רוצים להוסיף להן את אותה יכולת, הדרך הנכונה היא **אותו פורמט** (`design-tokens`)
עם טבלת תרגום לכל מערכת. זו **הצעה, לא משהו שקיים**:

**ערכת האתר** (`CustomAppTheme` ב-`src/contexts/ThemeContext.tsx`):

| שדה באתר | תפקיד מוצע | הערה |
|---|---|---|
| `background` | `background` | |
| `foreground` | `text` | |
| `card` | `surface` | |
| `accent` | `accent` | |
| `primary` | `accentAlt` | באתר `primary` הוא הכחול הראשי. צריך להחליט |
| `sidebar` | `backgroundGlowTop` | התאמה חלקית |
| `sidebarForeground` | `onAccent` | התאמה חלקית |
| `cornerRadius`, `shadow`… | — | כמפתח אח (`"appearance"`), לא בתוך `roles` |

**ערכת הסידור** (`SiddurTheme` ב-`src/pages/Siddur.tsx`):

| שדה בסידור | תפקיד מוצע | הערה |
|---|---|---|

עם טבלאות כאלה, ערכה אחת תוכל לעבור **מהסידור ללוח ובחזרה**. זה דורש החלטות
עיצוב (בעיקר `primary` באתר ו-`bg` כגרדיאנט בסידור), ולכן זה לא מומש.

## 14. רשימת בדיקה לפני שמביאים ערכה

**למנהל:**
- [ ] `format` הוא `"design-tokens"` ו-`version` הוא `1`
- [ ] כל הצבעים ב-hex (`#rrggbb`) או `rgba(...)`, בלי שמות צבעים
- [ ] `mode` נכון: `"light"` לערכה בהירה
- [ ] ערכה בהירה? למלא את כל עשרת התפקידים
- [ ] אחרי הייבוא לבדוק ב**חלון חי**, רצוי מהצד השני של החדר
- [ ] טקסט בתוך תגית הזהב (`onAccent` על `accent`) קריא
- [ ] מסך OLED: ערכה בהירה רק לשבת או לזמן קצוב
- [ ] **שמור ושדר**, ואז לבדוק את המסך האמיתי

**למפתח שמממש את הפורמט אצלו:**
- [ ] מחזור מלא: ייצוא ← ייבוא לאותה מערכת ← שתי רשומות, השנייה עם `(2)`
- [ ] קובץ עם 3 תפקידים בלבד ← ערכה שלמה ושמישה
- [ ] `version: 99` ← שגיאה ברורה
- [ ] קובץ עם גרדיאנטים בלבד ← עובד
- [ ] ניסיונות הזרקה (`url(`, `var(`, `;`, `}`, `image-set`, ערך ארוך, `javascript:`) ← נדחים
- [ ] ייבוא ל[`example-themes.json`](design-tokens-kit/example-themes.json) ← 3 ערכות, 2 גרדיאנטים, 0 דולגו
